# Pre-Implementation Decision Register

Status: pre-implementation, pre-measurement  

Purpose: record every choice that a future implementation session must preserve, qualify, or resolve without inventing a testbed value. This register does not replace EXPERIMENT_SPEC.md; the specification is the scientific entry point and this file is its staged decision gate.

## Status vocabulary

- FROZEN: the method or default is fixed by the present scientific protocol. Reopening creates a versioned protocol revision and cannot use confirmatory outcomes.
- DEFAULT_PENDING_QUALIFICATION: a recommended default exists, but capability or off-stand/stand evidence must qualify it before its freeze point.
- BLOCKED_ON_TESTBED: the decision cannot be resolved without the physical hardware or its validated capture.
- UNRESOLVED_SCIENTIFIC_DECISION: an investigator choice is required and must be justified independently of observed policy effects.

## Freeze-stage checklist

### Before off-stand implementation

The implementation must preserve D03, D11, D12, D21, and D23 exactly. It must represent every other row as a typed unresolved gate rather than supply a guessed value. Conceptual schemas, error statuses, digest rules, and the exact-small budget benchmark procedure are frozen before component implementation; D13's numerical limits are resolved by that benchmark.

### Before stand integration

D01, D02, D05, D06, D07, D08, and D09 must be resolved sufficiently to create one versioned frontend and environment profile. A failed mandatory capability remains explicit; it is not converted to a fallback that changes the baseline treatment.

### Before calibration

D04, D10, D16, D18, D20, and D22 must be resolved and frozen. The ownership catalog, feature order, transforms, condition/placement-relation coverage map, split/fold identities and admissibility results, timestamp domain, correctness gates, and calibration validity variables are content-addressed inputs.

### Before the confirmatory campaign

D14, D15, D17, D19, the fitted model artifact, all numeric acceptance thresholds, the fixed attempt schedule, any optional D23 attrition-sensitivity formulas (or explicit none), and every remaining baseline/read-back decision must be frozen. No decision may be reopened because of confirmatory latency, p-values, placement rankings, or attrition outcomes.

## Handoff rule

The exact entry point for the future implementation repository remains EXPERIMENT_SPEC.md, Milestone 1. Its first action is to import this register as the unresolved-decision ledger, preserve all FROZEN rows, and emit an explicit blocked status for any stage whose required rows are not yet resolved.
